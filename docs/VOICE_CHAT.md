# VoiceChat 0.1

Optional audio plugin for NullServers 0.0.66. NullServers includes forwarding and speaking indicators; VoiceChat.dll supplies microphone capture, playback and configuration. VoiceChat is deliberately absent from required room addons. It is listed in ADDONS as an optional official addon: disabling it there turns off the local microphone, playback and the Voice Chat menu entry, while a host keeps forwarding other players. Rooms never require it, and a room that lists it is treated as not requiring it. The host needs the updated NullServers, but does not need VoiceChat.dll to forward audio.

Hold V by default. Settings permits rebinding keyboard/mouse keys; Escape cancels binding. Q remains available for Building. Input is blocked outside an authenticated NullFrame room, while the cursor is unlocked, while typing, during settings and while the game is unfocused. A microphone is opened only while the talk key is held or an explicit local microphone test is active. A small initial device-start delay is expected. No recording is saved to disk.

The fixed protocol uses broadcast 0x4E56 on FishNet's unreliable channel. JSON frames are at most 640 bytes. Audio is mono 24 kHz, 480 samples per 20 ms frame, independent IMA ADPCM blocks (244 bytes), base64 encoded. This avoids an external native codec or executable download. It trades higher bandwidth for simple bounded decoding. Each sender uses about 12.2 KB/s of compressed audio, plus JSON/relay overhead. A 60 ms jitter buffer handles packet reordering; a lost frame fades out rather than replaying stale audio.

Host admission requires FishNet authentication and completed NullServers content handshake. The host stamps the connection's client ID, rejects duplicate/old sequence numbers and limits audio to 55 frames/s with a 10-frame burst. Receiver capability expires after 10 seconds and is refreshed every 3 seconds. Audio is sent only to listeners within 40 world units, using server player positions. Non-listeners receive a small activity update at most five times per second. These controls do not prevent a modified client from sending arbitrary sounds as itself; the host is trusted. Existing relay transport security still applies; voice is not end-to-end encrypted.

Playback uses a 3D AudioSource at the player's tracked position, linear attenuation from 2 to 40 units and no Doppler shift. This first version has no wall occlusion, echo cancellation or automatic gain control. Headphones are recommended for the two-person test. Volume, device, gain and key are saved under UserData/NullFrame/voice.json. Devices are selected by their Windows names; a missing saved device falls back to the first available microphone.

Unity 6 generated audio wrappers use span marshalling that fails in this game's interop assemblies. UnityAudio confines the workaround to the exact native audio icalls and native ManagedSpanWrapper layout. This bridge targets the current Unity 6000.0 Windows x64 game build and must be reverified after a Unity upgrade.

References: https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioClip.Create.html and https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioSource-spatialBlend.html.
